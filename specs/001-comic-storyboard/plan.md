# 技術規劃：漫畫分鏡與腳本草稿管理工具

**分支**：未建立（目前沒有 Git Repository；setup-plan 回報的 `001-comic-storyboard` 是功能識別值）
**日期**：2026-11-20 | **規格**：[spec.md](./spec.md)

**需求來源**：[漫畫分鏡與腳本草稿管理規格](./spec.md)

## 摘要

規劃一個單頁網頁工具，讓國小四至六年級學生建立漫畫草稿、編輯章節與分鏡文字、保存並匯出易讀大綱。已核准的候選技術棧為 React、TypeScript 與 Vite；草稿採同一瀏覽器設定檔的裝置端保存，不使用帳號、伺服器同步或公開分享。使用者介面與匯出內容使用台灣繁體中文。

## 技術脈絡

**語言／版本**：TypeScript 7.0.2；Node.js 22.12 LTS 系列（最低 22.12.0）。

**主要相依套件**：React 19.3.1、React DOM 19.3.1、Vite 8.3.8，以及相容的 React Vite 外掛。

**保存方式**：瀏覽器 `localStorage`，保存純文字漫畫草稿，直到創作者刪除或清除瀏覽器資料。不得傳送草稿至伺服器。

**測試**：Vitest 5.1.1 執行領域與保存邏輯測試；Playwright 1.65.1 驗證主要使用者流程及 Chromium、Firefox、WebKit 的瀏覽器行為。

**目標平台**：現代桌上型、平板及手機瀏覽器；版面須能因應不同螢幕寬度。

**專案類型**：單一用戶端網頁應用程式，不包含後端服務。

**效能目標**：以 10 個章節、100 個分鏡的驗收資料集測試；本機保存、重新開啟及匯出各須在 1 秒內完成。此為規劃基準，不是目前已有的實測結果。

**限制**：不建立帳號、不收集學生身分資料、不提供跨裝置同步或公開分享；同一瀏覽器設定檔的其他使用者可能看見草稿。瀏覽器可能封鎖或清除本機資料，系統必須明確處理保存失敗。所有學生可見文字及文件使用台灣繁體中文。

**規模／範圍**：單一創作者、同一瀏覽器設定檔、文字型草稿；不含圖片、多人協作、雲端同步、評分或發布功能。10 章、100 分鏡僅作為效能驗收資料集，不是內容上限。

## 憲章檢查

*關卡：Phase 0 研究前檢查；Phase 1 設計後重新檢查。*

### Phase 0 前

- **規格驅動與授權**：通過。依已審閱的功能規格進行規劃；本計畫不包含產品實作、提交或部署。
- **技術棧**：通過。專案方已核准 React + TypeScript + Vite；沒有既有應用程式碼或 Git Repository，沒有更換既有技術棧。
- **學生資料與隱私**：通過。成人教育者已核准同裝置保存至創作者刪除、不建立帳號且不同步。草稿不含身分欄位；需提醒共用瀏覽器設定檔的使用者資料可被其他使用者看見。
- **安全與錯誤處理**：通過。保存、載入及匯出失敗不得呈現成功狀態；刪除須再次確認。
- **語言及年齡適切性**：通過。介面以台灣繁體中文呈現，並以國小四至六年級學生為主要使用者。

### Phase 1 後

- **資料最小化**：通過。資料模型不包含帳號、姓名或其他學生識別資訊；保存範圍僅限創作草稿。
- **相容性及可靠性**：通過。本機資料集合包含版本欄位；無法讀取或保存時須保留目前畫面內容並顯示明確錯誤，不得靜默覆寫。
- **使用者體驗驗證**：通過。資料模型、UI 合約及 quickstart 驗證案例涵蓋建立、編輯、保存、刪除、匯出、鍵盤操作與錯誤狀態。
- **未解決的憲章關卡**：無。
