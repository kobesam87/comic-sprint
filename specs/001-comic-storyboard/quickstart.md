# 驗證快速指南：漫畫分鏡與腳本草稿管理工具

## 適用狀態

應用程式與測試已建立。本節記錄本次實際執行結果；本專案根目錄不是 Git Repository。

## 前置條件

- Node.js 22.12 LTS 系列（最低 22.12.0；符合目前規劃的 Vitest 版本需求）。
- npm。
- 支援的現代桌面或行動瀏覽器。
- 本次驗證環境：Node.js 26.13.1、npm 11.20.0。

## 啟動及檢查

```sh
npm ci
npm run dev
npm run test:unit
npm run test:e2e
npm run build
```

**本次實際結果**：

- `npm ci`：完成；npm 顯示 `fsevents` 安裝腳本未獲准的提示，安裝仍成功。
- `npm run test:unit`：20 項測試通過。
- `npm run test:e2e`：27 項測試通過，涵蓋 Chromium、Firefox 與 WebKit。
- `npm run build`：成功。
- 手動檢視：本機頁面正常顯示；新增分鏡後出現第 1 格及畫面描述／對話欄位；刪除草稿會先顯示確認對話框，確認後草稿移除。檢視用的測試草稿已刪除。

自動化驗收涵蓋草稿建立、編輯與保存、重新開啟、刪除、匯出、鍵盤操作、響應式版面及大型草稿效能。未進行學生使用者測試；該測試須先取得成人教育者對校務程序及家長／監護人同意的確認，詳見 `tests/usability/protocol.md`。

## 端到端驗收情境

1. **建立及保存**：建立漫畫草稿，新增兩個章節與多個分鏡，輸入畫面描述及對話並保存；重新載入後確認草稿及順序完整。
2. **獨立編輯**：修改其中一個分鏡的對話並保存；確認其他分鏡未變，重新開啟後新文字仍存在。
3. **匯出大綱**：匯出文字大綱，確認漫畫名稱、章節、分鏡、描述與對話均按原順序出現，且已填文字無遺漏。
4. **空白匯出**：建立尚無章節的草稿並嘗試匯出；確認工具顯示原因且沒有產生空白檔案。
5. **刪除流程**：取消刪除時確認草稿仍存在；再次確認刪除後確認草稿不再出現。
6. **本機保存失敗**：模擬瀏覽器禁止保存或保存空間不足；確認目前畫面內容保留，並顯示保存失敗而非成功訊息。
7. **個資與分享**：確認建立與編輯流程不要求學生身分資料，且介面沒有公開分享或登入功能。
8. **鍵盤及窄螢幕**：以鍵盤完成建立、編輯、保存及匯出；在平板及手機寬度檢查內容可閱讀且操作不被遮擋。
